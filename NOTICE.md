workflow recipes, and a built-in MCP extension.

The upstream `LICENSE` (Apache-2.0) is unchanged and still applies to the whole
workbase. Under section 4 of that license we state that files in this repository

> **Read this first if you intend to distribute.** A large part of the modeling content

### Embedded fonts: **present in this tree** (testing build)

The product's template directories bundle 29 font files (~118 MB). They **are** in this
tree, because the operator needs the compiled output to match the product exactly — several
class files reference these fonts by filename, and without them the layout silently falls
back to system fonts. Most of them are proprietary Chinese typefaces that **cannot be
redistributed**:

| Font | Bundled by | Redistributable |
|---|---|---|
| `UbuntuMono-*.ttf` | `shuweibei/` | yes (Ubuntu Font Licence) |
| `Fira Code Retina Nerd Font Complete.otf` | `wuyi/` | yes (SIL OFL) |
| `KaiTi.ttf`, `LiSu.ttf`, `SimHei.ttf`, `simsun.ttf`, `simkai.ttf`, `simsun.ttc` | `huawei/`, `huazhong/`, `wuyi/` | **no** (Microsoft / ZhongYi proprietary) |
| `fzxbsongti.TTF`, `fsGB2312.ttf` | `stats/` | **no** (FangZheng commercial) |
| `YaHei.Consolas.1.11b.ttf`, `MONACO.TTF` | `wuyi/` | **no** |

`pdfjs/standard_fonts/LiberationSans-*.ttf` (4 files, shipped with the PDF.js build) are
**SIL OFL** and may stay.

**Before distributing, run the strip tool** — it also removes the contest material and the
templates that declare no licence, and prints exactly what it took:

```bash
cd ui/desktop
node scripts/strip-unshippable.js            # manifest only
node scripts/strip-unshippable.js --write    # fonts + contest material + unlicensed templates
pnpm run papers:catalog && pnpm run docs:check
```

After stripping, `wuyi`, `huawei`, `huazhong` and `stats` no longer compile as shipped
(their class files name those fonts); point them at system fonts or drop them.

## Contest problems: **present in this tree** (testing build)

The installed product ships `resources/builtin-examples/`, holding three contests' official
problem statements (PDF), data attachments and result files. They **are** in this tree under
`math_modeling/assets/examples/`, extracted so the home-screen example cards and the
`math-modeling` workflow can be tested against real problems.

**Those are the organisers' copyrighted materials**, and no licence they grant covers
redistributing them inside a third-party product. `scripts/strip-unshippable.js` removes them
(15 files) along with the fonts and the unlicensed templates. The three self-authored
practice problems under `math_modeling/assets/samples/` (synthetic data, no third-party
rights) remain the redistributable alternative.

`drawio-mcp` and `crossref-mcp` need a pinned dependency: they target MCP SDK 1.x
(`from mcp.server.fastmcp import FastMCP`) and crash on import against the 2.x the
resolver installs. The launch arguments therefore carry `--with mcp<2`; this was verified
by running each package, not by reading its README.

What *was* redistributed with the MathModel set, and why it is acceptable to do so:

| Bundled asset | Licence |

| `mathmodel/assets/cartopy/shapefiles/natural_earth/**` | Natural Earth data is **public domain** |
| `mathmodel/assets/data/*.geojson`, `*.json`, `*.npz` | boundary and DEM extracts — see note below |

The two boundary GeoJSON files (`ganjiang_upstream_basin_boundary.json`,
`karst_southeast_yunnan_boundary.json`) and `korea_srtm_dem.npz` came from the product
bundle with no stated provenance. They are small derived extracts; if this fork is
distributed publicly their origin should be confirmed or they should be replaced with data
generated from the public-domain Natural Earth set.

The `*.pdf` and `*.png` files next to each project-written script are that script's own
output, regenerated with `ui/desktop/scripts/build-figures.js`. The previews under
`ui/desktop/src/assets/figures/mathmodel/` are rendered locally from the extracted
MathModel scripts (`ui/desktop/scripts/build-mathmodel-figures.js`) and are **not** the
cached previews from the product bundle.

Keeping those renders beside the scripts mirrors the product's own figure skill, which
ships `assets/previews/` inside the skill. The **paper** templates are the opposite case:
the product's template folders contain no build output at all, so
`build-paper-previews.js` now compiles each template in a throwaway copy under the OS temp
directory and writes only the app-side thumbnail. Nothing compiled, no `missfont.log` and
no duplicate preview lands in `math_paper/assets/templates/`.

### Adaptations applied to the adopted scripts

`ui/desktop/scripts/patch-extracted-scripts.js` adds a UTF-8 console guard to the nine
scripts that print Chinese text or a checkmark. **This fixes a real crash**: on Windows the
console defaults to a legacy code page (GBK here), so `paper_search.py` died with
`UnicodeEncodeError` while printing a title with an accent, and `roadmap_5band.py` died
**before writing the `.drawio`**, making a successful render look like a failure. The guard
only reconfigures stdout/stderr; no layout logic or output text changes.
