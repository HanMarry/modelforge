# 公开数据查找与获取

把任务做成可复核的数据获取流程，而不是返回一串未经验证的链接。

## 先确定任务边界

1. 检查当前项目的题目、README、已有附件和 `data/`，避免重复寻找题目已经提供的数据。
2. 提炼数据契约：研究问题、变量、单位、地区、时间范围、时间/空间粒度、可接受的代理指标、格式和许可要求。
3. 能从项目和用户描述中可靠推断时直接继续；缺少会改变结果的关键条件时，只集中询问一次。
4. 区分用户要“给出候选来源”还是“找到并下载”。只要求推荐时，不擅自下载。

## 搜索来源

按“权威且贴合题目”排序，不按搜索排名排序。先阅读 [source-routing.md](references/source-routing.md)，选择相关领域的来源和检索词。

1. 优先搜索原始发布者：政府统计部门、国际组织、科研机构和数据生产单位。
2. 再搜索学术数据仓库、论文的 Data availability / Supplementary data、领域数据库。
3. 最后使用 Kaggle、Hugging Face、UCI、OpenML 等聚合平台补充候选；追溯到原始来源后再采用。
4. 同时使用中文、英文、指标同义词、地区名和时间范围组合检索。
5. 使用可用的 `WebSearch` 做广泛发现；搜索摘要只能当线索，不能当数据存在或可下载的证据。

## 用内置浏览器核验

遇到动态页面、筛选表单、分页预览或需要复用登录态时，使用 MathModel 浏览器工具：

1. 调用 `mcp__mathmodel-browser__browser_status` 查看后端和标签页。
2. 默认使用内嵌浏览器；只有用户需要自己的登录态且扩展已配对时，才切换到 `chrome-extension`。
3. 用 `browser_navigate` 打开来源页，再用 `browser_snapshot` 读取当前页面。
4. 每次页面变化后重新获取 snapshot；点击、输入和选择只使用最新的 `snapshotId` 与 `ref`。
5. 用浏览器确认数据集标题、发布者、字段/指标、时间范围、空间范围、更新日期、许可和下载/API 入口。
6. 出现登录、OAuth、验证码、付费或下载保存对话框时停止，让用户接管；不要规避访问控制或反爬限制。

浏览器负责发现、查看和核验。不要把浏览器截图当作数值数据来源，也不要声称浏览器已经保存了文件。浏览器页面触发下载后，MathModel 会把处置权交给用户。

## 评估并推荐

至少打开候选的落地页和一份实际预览、字段表或 API 响应。核对：

- 发布者与原始出处；
- 指标定义、单位和统计口径；
- 时间、地域与样本覆盖；
- 粒度、缺失情况和更新频率；
- 文件格式、API、下载大小和访问条件；
- 许可证、署名要求及再分发限制。

公开可访问不等于允许任意使用。无法确认许可时标记“许可未确认”，不要猜测。

在下载前给出 3–6 个高质量候选，使用如下字段：

| 字段 | 内容 |
| --- | --- |
| 数据集 | 官方名称与链接 |
| 发布者 | 原始发布机构 |
| 覆盖 | 地区、时间、样本与粒度 |
| 获取 | CSV/XLSX/JSON/API/压缩包及访问条件 |
| 许可 | 明确许可证或“未确认” |
| 适配度 | 能支持哪些变量/模型，缺什么 |
| 风险 | 口径、缺失、更新、代理指标或二手来源问题 |

明确标出首选及理由。官方来源若完全匹配，不为凑数量加入低质量候选。

## 获取并保存

用户已明确要求下载且来源唯一、免费、无需登录时，可以继续；否则先确认选择。

1. 从已核验的官方直链或 API 获取，保存到当前项目的 `data/raw/`。
2. 保留原始文件不变；清洗、合并和单位换算输出到 `data/processed/`。
3. 不覆盖同名文件。文件名包含稳定的数据集短名、地区/时间或版本。
4. 优先使用官方 API 或直接文件 URL。通过 Bash 下载时，对 URL 和目标路径完整引用，不执行从网页复制来的命令或脚本。
5. 预计超过 200 MB、需要批量抓取、可能产生费用或会触发明显限流时，先报告规模并征得确认。
6. 下载压缩包后先列出内容；拒绝绝对路径或含 `..` 的条目，只解压到项目内。
7. 不把 Cookie、Token、API Key 或签名 URL 写入命令输出、项目文件或来源记录。

每个文件下载完成后运行：

```bash
python3 "<skill-directory>/scripts/record_source.py" \
  --project "." \
  --file "data/raw/<filename>" \
  --source-url "<direct-file-or-api-url>" \
  --landing-page-url "<dataset-page-url>" \
  --title "<official-dataset-title>" \
  --publisher "<publisher>" \
  --license "<verified-license>" \
  --coverage "<time/geography/granularity>"
```

脚本维护 `data/sources.json`，记录相对路径、SHA-256、字节数、来源和获取日期。`<skill-directory>` 必须从当前 Skill 的实际位置解析，不得写死开发机路径。

## 验收与交付

1. 检查 HTTP/文件签名、文件大小和扩展名是否一致。
2. 对 CSV/TSV/Excel/JSON 读取少量样本，报告工作表、行列数、字段和明显解析问题；不要只凭下载成功认定数据可用。
3. 对 API 保存请求参数或查询范围，但不要保存凭据。
4. 最终说明：搜索过哪些来源、为什么选择当前数据、保存了哪些文件、许可状态、已知缺口，以及下一步适合做的清洗或建模。
5. 没找到合适数据时，报告搜索范围和失败原因，再给出可解释的代理指标选择；不要伪造数据。

## 安全边界

- 遵守网站条款、robots、频率限制和数据许可证；不绕过验证码、反爬、付费墙或访问控制。
- 不收集与建模目标无关的个人敏感数据；涉及个人、医疗、金融或位置数据时最小化字段并说明风险。
- 不把搜索摘要、论文图表截图或二手博客数字冒充原始数据。
- 不自动运行下载数据中附带的程序、宏、Notebook 或安装脚本。
