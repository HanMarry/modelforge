# 分享论文到数模广场

不要向用户提问，也不要等确认。读完、脱敏、整理字段、上传，一次做完。

## 1. 找 PDF 并读全文

用户一般不会给路径：在当前工作目录里找出要分享的论文 PDF（通常是 LaTeX 编译产物，如 `main.pdf`）。有多个候选时选最像成品论文的那份（优先 `main.pdf` / `document.pdf`，其次最新、页数最多的），不要问用户。找不到再结束并说明原因。

用可用的 PDF 读取工具**逐页读完**。记下：页数、标题、竞赛名称、年份、题号、主要方法（用作标签）、摘要要点，以及下一节要删的敏感内容位置。

## 2. 敏感信息直接删掉

逐页找下面这些，命中就从**用于上传的副本**里删掉，不要停下来问，也不要改用户正在用的原稿：

- 姓名、学校 / 学院、学号、报名号、参赛队号、指导教师、队员签名；
- 手机号、邮箱、身份证号、地址、微信 / QQ 等联系方式；
- 竞赛承诺书、编号专用页这类整页行政信息；
- 致谢或页眉页脚里的可识别信息；
- 密钥、内部数据、第三方机密内容。

有 LaTeX 源就复制一份、删掉上述内容后重新编译，把编译出的 PDF 拿去上传。只有 PDF 就复制后删掉敏感页或涂掉对应内容。上传文件里不能再留这些信息。

正在进行的比赛的未公开解答、大段复制他人内容：不要上传，直接告诉用户原因（仍然不要提问）。

## 3. 整理公开字段

自己定，不要给用户确认：

- 标题
- 竞赛名称、年份、题号
- 一段 1–3 句摘要（从论文摘要提炼，不要照抄整段）
- 3–6 个方法标签
- 花费（元）：用首条消息里用户填的数字，原样传 `costCny`；没写就留空
- 使用的模型：本次会话实际使用的模型名称（不确定时用内置读取设置工具查看），不用问用户

## 4. 交付（本 fork 没有数模广场）

本 fork 没有广场后端，也没有 `upload_paper` 工具，**不要假装已经上传**。
把第 3 步整理好的字段写进项目根目录的 `sharing.json`，与脱敏后的 PDF 放在一起，
然后在回复里给出：PDF 绝对路径、`sharing.json` 路径、字段一览，以及一句
"本 fork 未接入投稿后端，请到赛事/社区平台自行提交"。

## 禁止事项

- 向用户提问、列清单等人确认、或等用户说「可以上传」；
- 上传仍含个人信息的原稿；
- 上传用户没有指定、也不是当前项目论文的其它文件；
- 在消息里输出任何凭据、签名 URL 或令牌；
- 向任何远端地址上传论文：本 fork 没有投稿后端，只在本机准备文件。
