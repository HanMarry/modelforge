# 数学建模论文模拟评审（结构化输出）

本技能按用户选定的赛事，对当前项目里的一篇论文做一次模拟评审。产物不是文件，而是**一个 JSON
对象**：桌面端「模拟评审」面板会校验它（6 个维度齐全、评分为 0–10 的整数、每维至少 1 条理由、
每条意见带位置），校验通过才保存为评审记录，并与该论文上一次的记录逐维对比。

与 `math-review` 的分工：`math-review` 在对话里评审并写 `review.md`，维度按参考产品划分；
本技能只产出结构化结果，维度固定为下面 6 个，供界面展示、保存和对比。

评审结果由模型生成，仅供参考，不代表任何赛事的官方评分。桌面端会在结果页顶部固定显示这句
提示，JSON 里不需要重复。

## 1. 输入与前置检查

请求会给出论文文件（当前项目内的 `.tex`、`.md` 或 `.pdf`）和赛事 id（取自
`ui/desktop/src/catalog/competitions.json`，即第 4 节表格的第一列）。

- 没有给出赛事、文件不存在、文件读不出内容时，**不要评审**：用一句话说明原因（未选赛事 /
  文件不存在 / 文件无法读取），不输出评审 JSON。
- `.tex`：读主文件，并顺着 `\input`、`\include` 读完所有章节；记下每节标题所在的行号。
- `.md`：按标题层级划分章节，记下行号。
- `.pdf`：逐页读完，不要只读摘要；记下每节标题所在的页码。图片里的文字读不出来时，在相关理由里
  如实说明，不要猜。

## 2. 六个评分维度

| 维度 | 看什么 | 常见扣分点 |
| --- | --- | --- |
| 问题分析 | 是否读懂题目、逐问拆解；目标、约束与已知条件是否讲清；数据是否先体检；方法选择有没有依据 | 照抄题干当分析；几问合成一问；没说明为什么选这类方法 |
| 模型假设 | 假设是否必要、合理、在后文被用到；是否说明假设不成立时的影响；符号说明是否完整、带单位 | 为凑模型硬加假设；假设与题意矛盾；符号前后不一致 |
| 模型建立 | 模型是否对应题目要求；变量、目标、约束或方程是否写清；推导有无跳步或错误；与替代方案的比较 | 只列公式不解释；模型与问题对不上；关键推导缺失 |
| 求解与结果 | 求解方法与参数是否交代、能否复现；每一问是否都给出数值结果；量级是否合理；是否与基线或已知结果对照检验 | 有问题没作答；只有"结果如图"没有数值；结果明显不合理却未解释 |
| 灵敏度分析 | 关键参数扰动后结论是否稳定；误差、不确定性与稳健区间；模型优缺点与推广是否具体 | 完全没有检验；只有一张扰动表不做解读；优缺点空泛 |
| 写作表达 | 摘要是否交代问题、方法、具体数值结果和结论；章节结构是否完整；图表是否规范并被正文引用；参考文献是否真实；篇幅与格式是否符合赛事要求 | 摘要没有数字；图缺坐标轴或单位；参考文献疑似编造；超出页数限制 |

## 3. 分档（每个维度一个 0–10 的整数）

| 分数 | 含义 |
| --- | --- |
| 0 | 该维度的内容完全缺失 |
| 1–3 | 有内容，但存在根本性错误或关键部分缺失 |
| 4–5 | 完成了一部分，有明显缺陷，会显著失分 |
| 6–7 | 基本完整、没有原则性错误，但论证或细节不足 |
| 8–9 | 完整、正确、论证充分，只有小瑕疵 |
| 10 | 可以作为范例，找不到实质性问题 |

本技能的封顶约定（为了评分前后一致，不是任何赛事的官方规则）：

- 有子问题没有作答：「求解与结果」不超过 4 分。
- 通篇没有任何灵敏度、稳健性或误差分析：「灵敏度分析」不超过 2 分。
- 摘要没有具体数值结果：「写作表达」不超过 6 分。
- 参考文献疑似编造：「写作表达」不超过 5 分，并在理由中写明是哪几条。

每条理由都要指向论文里的具体内容（章节、公式、图表或数值），不要写"论证有待加强"这类空话。

## 4. 各赛事的评分侧重

赛事 id 与 `ui/desktop/src/catalog/competitions.json` 一一对应。侧重只影响理由里强调什么、
修改意见怎样排序，**不改变第 3 节的分档标准**。下表的"依据"说明了每条侧重从何而来：标注
"已核实"的两项依据官方原文（2026-10-01 查阅）；标注"官方评分细则未核实"的赛事按一般建模竞赛的
侧重处理，评审时不要声称这是官方标准。官方原文也没有给出各项分值，分值一律按第 3 节分档。

| 赛事 id | 赛事 | 侧重 | 依据 |
| --- | --- | --- | --- |
| `cumcm` | 全国大学生数学建模竞赛 | 模型假设、模型建立、求解与结果、写作表达 | 已核实：《全国大学生数学建模竞赛章程（2023年修订稿）》规定"竞赛评奖以假设的合理性、建模的创造性、结果的正确性和文字表述的清晰程度为主要标准"，四项依次对应这里的四个维度（https://www.mcm.edu.cn/html_cn/node/9183046a45d10cedcd4bce2688fc98b3.html） |
| `mcm` | 美国大学生数学建模竞赛（MCM/ICM） | 写作表达（Summary Sheet 与英文表达）、模型假设（每条假设给出理由）、灵敏度分析（含模型优缺点） | 已核实：COMAP 的 2027 届《Contest Rules, Registration and Instructions》写明评委很看重 Summary，获奖论文常因摘要质量而胜出；要求陈述并论证合理假设，讨论模型怎样检验（误差、灵敏度或稳定性）及其优缺点；整份提交含附录不超过 25 页（https://www.contest.comap.com/undergraduate/contests/mcm/instructions.php）。英文论文按英文写作习惯评价 |
| `huashubei` | 华数杯 | 同国赛的一般侧重 | 官方评分细则未核实 |
| `diangongbei` | 电工杯 | 同国赛的一般侧重 | 官方评分细则未核实 |
| `mathorcup` | MathorCup | 同国赛的一般侧重 | 官方评分细则未核实 |
| `shenzhen` | 深圳杯 | 同国赛的一般侧重 | 官方评分细则未核实 |
| `apmcm` | APMCM 亚太赛 | 同国赛的一般侧重；英文论文按英文写作习惯评价 | 官方评分细则未核实 |
| `stats` | 统计建模大赛 | 问题分析（数据来源与质量）、模型建立（统计方法是否适用、前提是否检验）、求解与结果（结论的统计意义与实际意义） | 由赛事名称与主办方性质判断其为统计建模类论文；官方评分细则未核实 |

"国赛的一般侧重"即 `cumcm` 一行的四项。请求中的赛事 id 不在表中时，按这四项处理，并在
「问题分析」的第一条理由里注明"未找到该赛事的评分侧重"。

## 5. 修改意见与位置

- 每条修改意见写成 `{ "text": ..., "location": ... }`。`text` 先说问题，再给具体改法（补什么
  数据、换什么图、怎么改写），不要只说"建议加强"。
- `location.section` 写论文里的章节标题原文。
- 源文件是 LaTeX 或 Markdown 时，加 `lines: [起始行, 结束行]`：行号从 1 开始，含两端，
  起始行不大于结束行。源文件是 PDF 时，加 `page`：页码从 1 开始。
- 按对得分的影响从大到小排列；同一处问题只写一条。
- 论文确实没有可改之处时 `suggestions` 可以是空数组，但这种情况应当极少。

## 6. 输出

最终回复只包含一个 JSON 对象，不要附加解释文字。它必须满足本技能目录下的
`review-output.schema.json`，形状如下（示例内容，仅示意写法）：

```json
{
  "dimensions": [
    { "name": "问题分析", "score": 7, "reasons": ["第 2 节把三问分别对应到目标与约束，但没有说明为什么选用整数规划"] },
    { "name": "模型假设", "score": 6, "reasons": ["假设 3「需求服从正态分布」没有给出检验，也没有说明不成立时的影响"] },
    { "name": "模型建立", "score": 8, "reasons": ["式 (4)–(9) 完整给出了决策变量、目标与约束"] },
    { "name": "求解与结果", "score": 5, "reasons": ["问题三只给了示意图，没有给出最优方案的具体数值"] },
    { "name": "灵敏度分析", "score": 3, "reasons": ["只对单价做了 ±10% 扰动，没有解读结论是否改变"] },
    { "name": "写作表达", "score": 6, "reasons": ["摘要没有给出问题二的数值结果；图 5 缺少坐标轴单位"] }
  ],
  "suggestions": [
    { "text": "问题三补充最优方案的数值表（各地块面积与总收益），并与问题二的方案对比", "location": { "section": "5.3 问题三的求解", "lines": [212, 240] } },
    { "text": "对单价、产量与需求三项参数做 ±20% 扰动，给出最优方案保持不变的参数区间", "location": { "section": "6 灵敏度分析", "page": 14 } }
  ]
}
```

约束：

- `dimensions` 恰好 6 项，每个维度名出现且只出现一次，名称与第 2 节一字不差。
- `score` 是 0–10 的整数（不要写成小数或字符串）；`reasons` 至少 1 条非空理由。
- `suggestions` 的每一项都有 `text` 与 `location`，`location` 按第 5 节给出 `lines` 或 `page`。
- 不要输出总分、等级、获奖预测或 schema 之外的字段；也不要自己和上一次评审对比，对比由
  桌面端根据已保存的记录计算。
- 结构不合法的结果会被桌面端判为"评审未完成"而不保存，所以宁可重新检查一遍再输出。

## 7. 规则

- 只评不改：不修改论文，不在项目里写任何文件（需要文字版评审与修改时改用 `math-review`）。
- 不编造：理由与意见只依据论文的实际内容；读不到的部分如实说明。
- 判断参考文献真伪时可以用 `paper-search` 核验可疑条目；核不到的写"疑似编造"，不要直接下结论。
- 评审过程中如果读文件失败或被中断，不要输出不完整的 JSON。
